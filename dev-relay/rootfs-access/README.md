# Four-template host lower-page access observation (build stage)

The previous `mincore` inventory measured residency of files referenced by both Guests. It did not measure which lower file pages each Guest actually read. Historical access sets cannot be reconstructed after the Guests exited. The user replaced the 33-template plan with four short, already-built templates (two Go, one TS, one Java), two Guests each, to obtain the missing metric quickly.

This directory prepares an **original ae9c626 source plus optional observation delta**, not the UB implementation. Six runtime source paths differ: one feature declaration, one module export, the per-I/O context, local-file read wrappers, the ublk target's source binding, and the observer module. A seventh input is the standalone calibration example. The wire protocol, Cargo.lock, read/write results, sharing implementation and device limits are unchanged. The downloaded Python build packet embeds the public original source archive and these checksummed changes, not private workloads, credentials or runtime binaries. The AGENTS.md symlink alias is skipped when extracting compiler inputs; CLAUDE.md remains present.

`rootfs-read-trace` is off by default. The candidate build enables it only for the observation daemon. Each ublk request binds the current image.json path into IoCtx; context-aware local file reads emit successful byte ranges with source, device/inode, length, offset, direct-I/O flag and monotonic timestamps. Unmatched local reads remain visible with allowed_lower=false so a wrong whitelist cannot silently become a zero result. Missing context propagation is counted separately. There is no payload logging. This measures host backing-file reads caused by sandbox rootfs I/O, including Guest filesystem activity; it is not an application-level file-access audit.

When deployed in a later step, the candidate looks for a private, same-UID `<executable>.access-spec` file. Its format is output=<absolute new log path>, max_bytes=<1MiB..256MiB>, max_records=<1..1000000>, and one or more allow=<dev>:<inode>:<file_size> lines. The output parent must be canonical, private and owned by the daemon UID; output uses create_new. A separate status JSON publishes sequence, byte, drop/error/fallback counters every second. Failed initialization disables observation without changing I/O; a controller must reject missing/unhealthy trace evidence. Direct I/O records must not be counted as buffered pagecache accesses.

The planned reducer maps each source to its exact sandbox, validates all lower identities, filters a fixed workload window, forms each sandbox's accessed host-page set, and probes only those pages with mincore **as the file owner**. This prevents substituting full-file residency and avoids the previous root-privilege ambiguity and slow full-device scans. Shared bytes are the resident intersection; its ratio denominator is explicitly reported. Sequence gaps, dropped records, unsupported context calls, identity changes and truncated windows invalidate complete-sharing claims. The activation/controller/reducer and target calibration are subsequent steps; this build packet alone does not produce measurement data.

## Operator build only

Run the pinned `cow4_access_build.py build` packet as ordinary A/jwk. It uses existing Rust1.99 and the existing locked offline Cargo cache/target. It executes only the observer's overlaybd unit tests and builds uvm-ublk-daemon, then copies the candidate into its own report directory. It never overwrites installed binaries, starts a service/Guest, calls UB, changes permissions on existing devices or changes kernel settings. The candidate embeds its observation-patch digest, checked after copying to detect a concurrent unrelated shared-cache build artifact.

The v2 packet uses a separate build receipt and additionally compiles/runs a calibration example in its own private directory. It writes an owned 8MiB file, then performs actual buffered io_uring reads attributed to two sources: pages {0,1} and {1,2}, followed by a repeat read of {0,1}. The Python reducer must observe all three reads, including the warm repeat, exactly one common resident page (4096B), and a three-page resident union (12288B). An independent owner mincore check must see the whole 8MiB fixture resident. Thus a 100% resident file must produce only 4KiB of shared accessed cache, not 8MiB. No production lower is read/warmed by this calibration. Its files remain in the private report directory for audit.

On success return `ROOTFS_ACCESS_OBSERVER_BUILT_AND_CALIBRATED_NOT_DEPLOYED` with the candidate SHA. On failure return the bounded compiler log tail. Do not install or restart it manually. The frozen build fails rather than downloading missing dependencies or upgrading a toolchain. Existing target-cache reuse is not a guarantee of zero compilation time. Application of this candidate must preserve and restore the original daemon configuration and verify empty inventories before any service transition.

Local checks: three portable Rust tests; ARM64 observer-module type check and Clippy; four source-packet integrity/scope tests. ## Scope audit and next field gate

The reviewed local-file chain is ImageFile -> LSMT data mapping -> SwitchFile/ZFile -> TarFile offset adapter -> LocalFile. Context-aware variants propagate the source; ZFile requests encoded block bytes, so reported offsets identify the host backing format, not the decoded Guest file offsets. Existing index/jump-table metadata can live in daemon memory; this metric does not count it as host file-pagecache data. Kernel buffered reads are recorded even when pagecache supplies the data. Guest RAM filesystem cache hits that issue no host lower read are not fabricated as host accesses. Prefetch/read-ahead pages not in an observed backing read range are excluded from demand-access sets. The controller must bind actual local runtime lowers and reject unsupported context fallback, unknown source, dropped records or incompatible IO modes rather than calling partial evidence complete.

The user reauthorized only four templates after the 17-template post-exit residency supplement failed to answer the access question. Choose the shortest first-batch representatives covering Go/TS/Java, retaining existing snapshots. Do not use the old 33-template runner unmodified. Build/calibration is the current operator gate; activation, bounded four-template lifecycle, live checkpoints and service restoration still require their own reviewed controller. No build-success status implies a completed Guest experiment. In particular, the host ublk limit remains64 and other sessions retain devices: an original-service restart changes its device pool, so capacity and all owned resources must be checked immediately before activation, without deleting unrelated devices.
