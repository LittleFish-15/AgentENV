# Paired original AgentENV memory accounting relay

Development-only measurement tooling. This directory is separate from the
upstream-facing implementation. It contains target-specific paths and pins;
remove it when preparing the core contribution for upstream review.

`../cow4_memory_pair.py` is generated by `make_packet.py`. It reuses the two
previously executed, SHA-256-pinned local packets and their existing binaries:

1. Original `ae9c626` server, original read observer, rootfs/memory I/O limits
   256/256 KiB.
2. Original-based `9a2fcf6` server, same observer logic, rootfs/memory limits
   64/256 KiB.

No compilation, image download, UB SDK call, B access, driver modification or
direct SSH connection is performed. Each group restores the same four existing
templates into eight Guests, runs the same continuous replays, releases owned
Guests and restores the original service. The groups run sequentially. The
second group checks the first group's complete lifecycle and matching template,
catalog, replay, lower inode and boot identities before activation.

## User relay

Run the pinned packet as the ordinary experiment user on A:

```
python3 -I -B cow4_memory_pair_<commit>.py run --quiet-window-confirmed --accept-nonzero-baseline
```

It prints one literal `/usr/bin/python3 ... COW4_MEMORY_PAIR_ROOT` block. Paste
that entire block into A's root terminal within 600 seconds. Leave both
terminals open. There is no `done` input and no separate second-group launch.
The root body does not import or execute a mutable user-side Python script.

The approved experiment includes **four host-wide page-cache drops**, two per
group, at the same idle/replay boundaries as the prior experiment. Coordinate a
quiet window because these drops affect other host readers. Actual residual
pages are recorded; a globally atomic zero-cache state is never assumed.
No further drop occurs during replay. Original service activation/restoration
is guarded by exact configuration/binary hashes and an empty Guest inventory.
An unknown mutation or uncertain Guest cleanup stops progression and preserves
the state for review. Do not manually replace binaries or restart services.

`status` reads the pair receipt. An existing receipt prevents an implicit repeat;
failure requires review rather than deleting pending files and rerunning.

## Accounting views

|View|Measurement|Target cadence|
|---|---|---|
|Host|Cached, Buffers, AnonPages, Shmem, Dirty, Slab, PageTables and other meminfo counters|1 s|
|File cache|Existing full rootfs lower, accessed-rootfs subsets, upper and experiment files; template memory lower files|15 s|
|Memory ublk cache|Live-bound device mincore, identity and consumers, deduplicated across Guests|15 s|
|FC process|One status and one smaps_rollup read per sample: RSS/PSS, Pss_Anon/File/Shmem, private/shared fields|1 s|
|Guest RAM vs FC overhead|Authoritative FC Guest regions intersected with smaps VMAs; no size-only guess|15 s|
|Common services and collector|Bound original Runtime/daemon and measurement-helper RSS/PSS|15 s|
|Physical sharing diagnostic|Stable paired pagemap reads, special-page separation, no raw PFNs emitted|B1 and T2 only|

Sampling is sequential, not atomic. Actual timestamps and duration are retained;
the extended sampler waits at least 15 seconds after its last scan. Device
mincore and VMA residency are **occupancy**, not evidence of actual per-Guest
memory accesses. Private CoW pages inside file-named VMAs remain included.
Missing fields or clipped VMAs are NA rather than scaled estimates or zeros.

PFN diagnostics use soft time and resident-page budgets. They can be unavailable
while the occupancy accounting succeeds. They run before the idle/replay cache
clears and after replay, not inside the trajectory. Paired snapshots are not an
atomic all-Guest physical-memory snapshot. Zero/KSM/compound/unclassified pages
are separated. Stability failures must not be replaced by RSS-minus-PSS.

The memory-device cache and file-backed Guest mappings can describe the same
physical pages. Do not add device cache to Guest RSS/PSS. Do not add whole-host
Cached to process RSS/PSS. The memory lower ordinary-file cache is distinct from
the memory ublk device mapping; keep Host Cached and Buffers as separate counters.
The target kernel's exact accounting remains an empirical reconciliation task.

## Lifecycle observations and output

- B0: original empty service; before the group's activation.
- B1: eight Guests ready, before idle clear; includes the first PFN diagnostic.
- B2: measured post-clear replay baseline, before launching trajectories.
- T2: replay finished, before Guest cleanup; second PFN diagnostic.
- T3: all owned Guests have exited, observer service remains; three scans over
  approximately ten seconds. Released device names are not queried as old cache.
- T4: original binary/config restored and healthy, with a final occupancy scan.

Each group retains original `combined-summary.json`, `process.jsonl`,
`access-cache.jsonl`, `host-cache.jsonl`, plus `memory-accounting.jsonl` and
`memory-accounting-summary.json`. The pair directory contains:

- `memory-comparison.json`: both groups' full memory summaries, Host/cache
  timeseries, template/Sandbox identities and source-report hashes.
- `memory-comparison.md`: collection/coverage index.
- `return.json`: pair lifecycle receipt.

PSS totals are computed within each sampling cycle before extrema are taken.
Independent process maxima must not be summed into a simultaneous peak. The
existing per-template RSS/PSS/min/max report is preserved. The pair's collection
status is not the final expert analysis: return its JSON and Markdown along
with the owner/root receipts for plotting and same-baseline reconciliation.

## Local verification

```
python -I -B dev-relay/memory-accounting/make_packet.py
python -I -B dev-relay/memory-accounting/test_pair.py
python -I -B dev-relay/rootfs-io64/test_trial.py
python -I -B dev-relay/rootfs-io64/test_recheck256.py
```

Portable tests cover mode/order gates, unchanged embedded baseline helpers,
same-cycle PSS, missing/unstable measurements, VMA classification, device
deduplication and real temporary-file/hardlink restoration. Linux proc/sysfs,
systemd and target ownership are simulated. These checks are **not** evidence
that the new target experiment has run or that every target counter is available.
