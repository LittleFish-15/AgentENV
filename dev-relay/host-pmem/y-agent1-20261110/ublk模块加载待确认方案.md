拟执行操作：再次核对运行内核、模块摘要和 vermagic；要求当前没有 ublk 模块或设备、模块加载未被禁用、无 lockdown 且操作具备 CAP_SYS_MODULE。将已核对的模块字节复制进 root 所有的私有暂存目录，之后只对该受保护文件执行 `insmod ... ublks_max=10240`，不使用任何 force/忽略版本参数。10240 是允许的设备上限，不是立即创建这些设备。

不会替换内核、修改启动项、重启、停止服务或卸载其他模块。完成后读取模块、控制节点、参数、taint 和内核日志，回传结果。失败时不强制加载、不盲目重试或自动卸载。

这仍是全机运行内核变更，不能与普通 jwk 进程级隔离等同。该模块是外部构建且未签名，加载可能设置外部/未签名模块 taint 标记，卸载通常也不会清除标记；完全匹配版本与成功构建不能保证零风险。因此根据用户此前“不影响 root 和其他用户”的约束，实际加载需要明确确认。仅 GitHub 读写持续授权不视为已经同意这项全机内核操作。

模块加载成功后再配置 jwk 专用设备授权、命名空间、数据/运行目录、密钥和服务；本步骤本身不表示 aenv 已可用。
