# Y 入口 TLS 兼容修复 v2

用户在 Y 的 root 终端遇到 Python GitHub 请求 HTTP 0、curl 证书链自签名错误，明确要求给相关请求增加 `-k`。

本版本将首次安装的两次 curl 下载均设置为 `-k`，将 Y 入口专用 GitHub 客户端的 HTTPS context 设置为不校验证书与主机名。该配置对本入口的控制仓库读取、固定源码下载和结果上传都生效；不修改宿主机或 Python 全局 TLS 配置。HTTPS 证书校验关闭，脚本固定提交、字节数、blob 和 SHA256 校验保留。后续 Y 部署任务涉及同一网络环境的 curl 下载时也需沿用此约定并保留产物摘要校验。

逐字节核对确认 v1 固定入口使用真实换行，不存在换行生成错误。本版本增加回归检查，保留原固定入口内容。

原 v1 脚本与发布记录保留。更新前检查没有 Y 已登记身份、执行队列或首轮登记回执；如存在则停止更新并先核对已有执行状态。v2 使用新的源文件和固定提交，不覆写已发布 v1 脚本；A/B/X 队列不变。当前仍只下发只读盘点，不启动 AgentENV 服务或压测。

首次使用 root 终端运行新安装器。原先认证未通过时，token 尚未保存，需要重新隐藏输入。安装后固定命令仍为：

```bash
bash /home/jwk/y-aenv-control/root-start.sh
```
