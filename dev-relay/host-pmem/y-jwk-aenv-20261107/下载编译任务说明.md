# Y：下载源码并编译

本轮先下载固定源码，再以 jwk 编译；不因 KVM/ublk 尚未就绪而阻挡构建。

源码来自 boostkit AgentENV 的 `5ca17126c51ce1ac1cfaf31cf50d902ab54d55b7`。本机会从该 Git 提交导出完整跟踪文件，经 GitHub 分片传递到 Y。Y 校验每片与完整归档的 SHA256，再核对原始 Git tree 和 commit 对象，恢复只含该提交的浅仓库；提交及跟踪文件不另行改写。之后应用 X 的四文件初始化预热补丁，并记录 dirty diff 和锁文件摘要。这样 Y 编出的程序可以保留原始 Git commit，具体补丁单独记录。

目录为 `/data/jwk/aenv-y-20261107`，源码放在 `source/AgentENV-5ca17126`，Rust 1.91.1 安装到专用 `deps` 目录，产物放在 `build/target/release`。root 仅创建专用目录、通过 openEuler 的 dnf 安装构建依赖；源码还原、Rust 安装和 cargo 编译均以本机 jwk（UID 1000）执行。Rust 分发包的 SHA256 在控制端从官方地址取得并固定进任务，Y 下载后核验。

构建 `server`、`aenv`、`uvm-ublk-daemon`，使用 `--locked --release -j 4`，并记录编译器版本、二进制 SHA256、架构及动态依赖。任务总时限三小时，保留至少 128 GiB 系统可用内存；详细构建输出保留在 Y 的 `build-logs`，失败回传阶段和日志尾部。已有构建状态不自动覆盖或重试，需要先核对回执。

按用户要求，GitHub 与 Rust 下载使用 curl `-k`；本次 Cargo、Git 和 dnf 请求使用相应的局部证书兼容设置。源码与 Rust 归档摘要继续核验，RPM 签名检查保留，不修改全局 TLS 配置。

本轮只记录 `/dev/kvm`、`/dev/ublk-control`、CPU svm 标志和模块信息，不加载模块，不改变内核、THP、NUMA 或邻居表参数。编译成功后再部署 jwk 服务、准备原生模板，最后执行预热及 run.sh。当前不能把“构建任务已发布”表述为“已编译成功”。
