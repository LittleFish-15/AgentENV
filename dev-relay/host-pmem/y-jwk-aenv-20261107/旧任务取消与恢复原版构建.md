# 旧任务取消与恢复原版构建

诊断004已经回传真实证据：旧 build002 的 root 管理进程 PID3404729、启动标识1978071 已被 PID1 接管；其 runuser/curl 子进程仍在下载 Rust。依赖安装成功结束，源码已按旧任务应用补丁，但尚未进入 cargo 编译。原版无补丁 build003 没有 state、task.py 或构建目录。旧入口缺少最终 report，因此原版任务被保护逻辑拦住。

GitHub 队列更新只影响后续领取，不会停止已经脱离入口的子进程。不能仅删掉 running 标记继续，也不能声称旧任务从未执行。

修复005为一次性 root 对账操作，不伪装成只读任务，也不改统一入口的保护代码。它先取得同一执行锁，核验私有计划、机器/启动身份、原任务描述与源码摘要、原 running 状态摘要和已审核诊断回执，再用 pidfd 绑定实际进程，取消旧任务及其已确认的子进程。出现新进程、PID身份变化或未完成的包事务等不符合证据的情况时停止，不按进程名称批量终止。

确认旧任务进程全部结束后，保留原状态副本和全部旧目录、源码、日志，补充明确的取消回执：outcome 为 cancelled_superseded_after_verified_diagnosis，buildSucceeded=false。旧任务的终态 report 使用 completed 表示该次执行已被对账关闭，exitCode=125 表示控制器取消结果；它不是成功构建，也不是猜测恢复出的原进程退出码，原进程退出码单独记录为 null。重复领取旧任务会停止，不重新执行。

修复任务通过独立005回执上传，不覆盖任何旧的 GitHub 不可变结果。随后自动进入原统一入口运行 build006。这个一次性修复需在 root 终端按固定提交和 SHA256 校验下载执行；之后仍使用原统一入口。

build006继续使用 X 原始 ae9c626 归档，不应用任何源码补丁。仅改善构建包装：Rust 下载允许断点续传、单次上限3600秒，最终仍核验固定官方 SHA256；可以复用旧目录里的公共 Rust 下载片段，不能复用旧 AgentENV 源码或构建结果。若入口监督进程退出，构建包装会停止本阶段子进程，避免继续成为孤儿任务。当前仍未在 Y 执行取消或开始原版构建，须等待现场运行修复命令的回执。
