# Y 的 jwk AgentENV 部署与测试

目标是在 Zen4/x86_64 的 Y 上建立 jwk 专用服务，通过 GitHub 手动领取任务、执行和回传。统一入口本身以 root 运行，构建、server、Firecracker 和 SDK 测试使用本机 jwk 的实际 UID。复用 A/B 的提交与 SHA256 校验、独立队列、执行去重、上传失败补传和未知状态停止机制。Y 使用独立的 `y-aenv-20261107-v1/node-y`，不修改 A/B/X 队列。

## 依赖实际回执的执行顺序

1. 首次安装入口，核验 EPYC 9654/x86_64、登记机器与启动身份，只读盘点服务、端口、配置、KVM/ublk 权限、源码、原生资产和 Wikidata 模板，回传私有结果。这个任务不安装依赖、不启动 server、不创建沙箱，也不修改宿主机参数。
2. 根据回执准备部署任务：固定 boostkit 源码提交 `5ca17126c51ce1ac1cfaf31cf50d902ab54d55b7`，应用 X 的四文件初始化预热补丁，使用 Rust 1.91.1 原生构建。为 jwk 建立独立目录、状态、运行目录、日志、密钥和 systemd 服务。处理现有端口或设备冲突时停止并回传具体占用，不结束其他服务，不卸载 ublk 模块。密钥仅在 Y 本地生成并以 0600 保存，不经 GitHub 传递。
3. 准备 x86_64 的 Firecracker、Guest kernel、envd 与 stock Wikidata-717 模板。历史模板 `01a17713-81c6-7e23-ace9-b9d2ebd86ec7` 只作为候选；先核验架构、2 vCPU/4096 MiB 和构建来源，再决定能否复用资产。jwk 服务使用独立的模板状态。X 的 ARM 快照不可复用；stock 与 java-followup 不当作同一模板。
4. 安装用户命令和 `run.sh`，验证服务实际 UID、API、ublk daemon 及设备存活，确认能创建、暂停、恢复和删除。正式测试前等到实际 `Not started` FC 数达到 1000，不能把全部 FC 进程数当成待命数。
5. 使用同一份 benchmark、`e2b==2.37.0`，预热一次完整生命周期，再执行 100 沙箱、并发批量 100、10 轮正式测试。`run.sh` 的默认轮数保留 X 当前的 5 轮，支持传入 10；首轮验收明确使用 10。每轮不额外插入等待，不重试正式操作，每次生成独立结果目录。

Y 尚未执行首轮盘点，因此当前不能确认依赖和资产路径，不能声称服务已经部署、测试已经通过。首轮回执到达后，本会话据此完成后续脚本并发布；这是依赖真实机器信息的分步执行，不另设重复审批。

## 对齐 X 的参数

| 项目 | Y 目标 |
|---|---|
| 服务用户 | jwk；UID 从本机读取 |
| 服务名、数据目录 | 建议 `jwk-aenv-y.service`、`/data/jwk/aenv-y-20261107`；盘点后固定 |
| API | 建议宿主 `127.0.0.1:18080`；核验占用后固定，记录代理与直连路径 |
| 水位 | 低 300、高 1000 |
| FC 初始化 | `startup_prewarm=true`、`startup_size=1000`、`fill_concurrency=4` |
| 正常 fill target | 初始仍为 300，保留取用低于低水位时的动态增长逻辑 |
| 沙箱 | stock Wikidata-717，2 vCPU、4096 MiB，原生 x86_64 |
| envd | 轮询间隔 3 ms，总等待上限 60 s，单次健康探测上限 1 s |
| 阶段采集 | JSON、span close；核对实际日志过滤器后记录完整设置 |
| 正式测试 | 100/批，10 轮；预热一次不计入 |
| 统计 | 原始秒保留，展示统一 ms，mean/P50/P95/max/wall |

X 的 ARM TLBI 补丁不适用于 Y。Y 的 HZ、CPU/NUMA、SMT、Swap、Guest kernel 和 Firecracker 版本单独记录，不将两机差异直接归因于 CPU。部署任务不自动换内核、重启、关闭 Swap 或清缓存。

## 详细耗时和验收

每轮输出 SDK create/pause/resume/delete 表，另按同一 sandbox/request 关联 `create_sandbox` / `resume_sandbox`、`launch_sandbox`、`start_resume`、`load_snapshot_file`、`wait_for_ready`、envd poll 和 envd init。父 span 已含子 span，不重复求和；缺日志记为缺失，不能写成 0。SDK 减去服务端 span 的差额包含多项开销，不单称 HTTP 时间。

采集每轮开始/结束的 FC 待命数量、补池事件、ublk 状态、IPv4 邻居表失败增量和机器负载，分析波动是否与这些事件重叠。已有健康的邻居表大阈值保持不变，任何必要增大都需在任务中记录原值、目标值及实际结果。不会在部署时重做 X 的短时降阈值诊断。

验收要求：1000 个实际待命 FC 就绪；预热成功；4000 次正式操作成功；summary 的 `valid=true`、`remaining=0`；服务和 FC 属于 jwk；现有 root 服务未被停止。失败时保留原始日志和状态，不删除任务状态以绕过去重，也不自动重跑压测。

## 固定入口与凭据

首次执行发布的 `Y_INSTALL_ONCE.sh`，脚本按固定提交下载入口，并核验 SHA256 和字节数。没有凭据时，通过终端隐藏输入两枚 fine-grained token：`AgentENV-relay-control` 的 Contents 只读、`AgentENV-relay-results` 的 Contents 读写；不选全部仓库。不把 token 发到聊天或写入命令。可在 [GitHub token 设置](https://github.com/settings/personal-access-tokens/new) 创建。保存位置为 Y 本地 root 所有的 `/home/jwk/y-aenv-control/relay/credentials.json`，权限 0600。

以后每次领取本轮任务均使用：

```bash
sudo bash /home/jwk/y-aenv-control/root-start.sh
```

入口执行一轮后退出，不后台轮询。重复执行已完成任务只补传结果。当前首次任务有效期至 2026-11-21 00:00 UTC；过期后更新任务，不绕过时间校验。若机器、内核或未知执行状态发生变化，先由本会话核对回执再继续。
